FROZEN P0
Product: an invitation-led Web3 specialist exchange where members contribute useful work, obtain complementary expertise, build attributable reputation, progress through an evolving membership NFT, and complete scoped earning opportunities.
Primary user: an active crypto participant with a demonstrable specialty and recurring needs outside it.
Scope: one shared research question, three complementary specialties—protocol research, on-chain data/risk, and opportunity operations—and one complete contribution-to-recognition journey. A Robinhood Chain example may supply the demo context.
P0 includes:
- Membership: real Robinhood Chain testnet NFT issuance, ownership verification, member binding, and Bronze/Silver display states. The NFT transfers; personal reputation, points, rank, and earned balances do not. Transfer revokes the previous ownership-derived access.
- Research exchange: specialist findings, visible missing coverage, documented cross-domain usefulness, and a follow-up peer request.
- Contribution and provenance: stable records with claims, author roles, sources, evidence, observation/submission times, versions, lineage, permissions, limitations, and corrections.
- Review: an authorized person other than the author accepts within a stated scope or requests correction. Disputes receive independent review.
- Recognition: one award ledger provides lifetime XP and seasonal points. Reputation remains contextual work evidence. Promotion requires human assessment. Numerical awards, thresholds, and capacity limits remain configurable demo defaults.
- Progression: demonstrate Bronze-to-Silver advancement on the same NFT, with peer-request initiation as the proposed tangible Silver benefit. Higher tiers are explained without presenting unbuilt services as available.
- Grind Intelligence: an inline evidence brief showing accepted findings, attribution, shared sources, corrections, and missing evidence. It respects permissions and updates from actual records. An LLM is optional.
- One earning action: a fixed-fee assignment with a named funder, deliverable, acceptance terms, rights, dispute route, and payment status. Real payment depends on committed funding; testnet settlement must be labeled as having no monetary value.
Purposeful blockchain requirement: membership must genuinely exist on Robinhood Chain and affect access and the evolving credential experience. Ownership and relevant transactions must be independently inspectable. Technical Architecture chooses the minimum implementation; separate provenance commitments, review attestations, rank transactions, and automated payouts are not mandated.
Accounts, submissions, review, permissions, awards, progression, NFT behavior, and brief updates must work. Seeded people, history, findings, or payment examples remain visibly labeled. A demonstrated promotion requires genuine prior evidence or an explicitly identified demo persona.
Premium collective subscriptions, additional active tiers, marketplace, team management, escrow, advanced AI, and token economics remain outside P0.
Final screen-by-screen flow
Screen	User flow	What it proves
1. Join / Membership	View a public sample → authenticate → verify wallet → issue or bind membership NFT → enter	NFT membership provides real access
2. Research Workbench	Read complementary findings → inspect sources → record useful cross-domain input → take the scoped assignment	Specialists help where another member’s expertise ends
3. Submit Finding	Add claim, evidence, sources, added value, lineage, limitations, and permissions → submit	Useful work becomes attributable evidence
4. Review Desk	Different authorized reviewer checks the work → requests correction or accepts with reasons → finalizes credit once	Recognition follows accountable assessment
5. Contribution Record	Inspect versions, sources, review, recipient use, and assignment/payment status	Provenance, usefulness, recognition, and earning remain connected
6. My Membership	Inspect XP, points, domain history, and promotion evidence → steward approves eligible advancement → same NFT displays Silver	Progression belongs to the contributing person
Return to Workbench	See the updated evidence brief → initiate a follow-up peer request	The completed contribution creates a reason to return


Technical Architecture handoff
Translate this frozen scope into the minimum stack, data model, contracts, permissions, and build sequence. Preserve the separation between member identity, NFT ownership, earned reputation, entitlements, and compensation.
Choose the smallest Robinhood Chain implementation that delivers real membership and correct transfer behavior. Keep sensitive content, points, and revisable reputation off-chain. Justify any additional on-chain mechanism by a P0 user requirement.
Model contributions, versions, sources, reviews, usefulness reports, awards, permissions, and agreements as linked records supporting the evidence brief. Treat operating numbers as configurable defaults.
Acceptance checks must cover the complete journey, unauthorized access, self-approval prevention, duplicate awards, correction propagation, NFT transfer without reputation transfer, and truthful transaction/payment states. Preserve the six screens and the ≤3-minute demonstration; do not add ecosystem features.
