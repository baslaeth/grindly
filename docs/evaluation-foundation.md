## Evidence Coverage

All categories use checklist `2026-09-30.2`, plus the selected contribution-type
questions. Required context accepts explicit Unknown or Not applicable. Server
validation rejects omitted fields; an empty object is not complete context. An
unknown answer is a gap for review, not verification. All records preserve server
submission time, original linked-message time, separately self-reported first
notice, attribution and immutable corrections. Unsupported identifiers retain

Common core: subject, main finding, relevance, evidence, personal addition and
uncertainty. New finds, guides and warnings do not require a price prediction.
Predictions require a horizon and criteria recorded before a new outcome. Later
versions cannot erase the original claim or its outcomes.

Read-only retrieval permits `docs.robinhood.com`, `docs.chain.robinhood.com`,
`ethereum.org`, `docs.cdp.coinbase.com`; three links maximum, HTTPS without
credentials/query/fragment/custom port, no redirects, 8-second/250-KB bounds.
Other links remain human-readable references. Images are human-review evidence.
Coinbase calls use fixed BTC/ETH product paths, validated times/OHLCV and bounded
bodies. The historical probe retrieved 24/24 hourly buckets; this is not proof
of any member forecast. Primary docs and current data can be stale or partial.
See `evaluation-foundation/source-probes.json` for exact probe times and statuses.

## Review and Model Boundary

Reviewers assess evidence, relevance, personal addition, limitations and competing
explanations in five short qualitative fields. The versioned assessment and exact
decision are persisted atomically with the existing one-time award mechanism.
No category score, new award amount or reviewer authority is created.

Source refresh never calls a model, even if a credential later appears. OpenAI is
the approved future provider; real invocation and semantic/injection performance
remain BLOCKED/unverified by owner choice. No sample card is created. Future
output must cite supplied retrieved evidence with an exact excerpt, supplied
date and claim-specific explanation. Unknown/contradictory/missing evidence stay
distinct. Citation validity alone does not prove reasoning is correct. Member
text, source excerpts and messages cannot grant permissions, approve or award.

Prior-work lookup includes permitted earlier versions, their original authors
and dates. Source/subject/identifier/wording similarities are hints, never copying
accusations. Hidden versions and even their match existence are withheld. No
cross-rank semantic search is exposed. The bounded lookup examines up to 60
earlier candidates, prioritizes matching subjects/identifiers and returns up to
12 hints; it does not establish exhaustive originality.

## Outcomes and History

Review Desk -> Due outcomes -> alpha -> Later outcome -> Record independent
outcome. Only a currently authorized, independent same-rank, demo-compatible
category reviewer can submit. The record names observed facts, observation time,
sources, uncertainty, comparison with original criteria, scope and conflicts.
Known/met, known/not-met, mixed, inconclusive and pending are separate states.
No outcome action creates XP or retroactively changes acceptance. Repeated
requests retain one record. New observations append history rather than replace it.

My Profile -> Category record -> category -> Versions, decisions and observations.
Filters cover category, pending, corrected, due and observed records. Counts use
explicit permitted-submission denominators and include outcomes on old versions.
Dates/durations are displayed without invented short/long cutoffs or a win rate.
Due checks are manually triggered at this checkpoint. Automatic scheduling is
NOT IMPLEMENTED and must preserve these same permission, scope and date checks.

## Founder Walkthrough

Current review URL: http://localhost:3000/. This is local, not production.

1. Open Home -> Enter Hub. Only the ten rooms of the currently verified NFT rank
   appear. Use top-right My Profile to inspect existing history and Claim $GRIND,
   which remains disabled. Profile focus never grants reviewer powers.
2. Hub -> category room -> Submit alpha, or use a message's Submit alpha action.
   Pick any of the nine categories and the actual contribution type. Start with
   a real guide/find, a sourced warning and, only if appropriate, a prediction
   with a future horizon. Supply your own evidence; nothing is sent for you.
3. At the current shared-schema checkpoint, the form is inspectable but saving
   is unavailable until migration 026 is explicitly approved and applied. Do not
   mistake this for an AI-key requirement; no key is needed for ordinary saving.
4. After migration and live verification: Submit -> saved version/time receipt ->
   alpha page. Same-rank members can read member-visible pending work; sensitive
   review-only work retains its restriction. Click Review Assistant for source
   observations and missing information. Refresh sources does not invoke AI.
5. Add sourced feedback or a linked correction. Genuine work waits for an
   independently authorized category reviewer; the founder cannot self-approve.
   Acceptance is not a forecast result or promised XP. Genuine category awards
   remain blocked until an approved rule exists.
6. At a declared due horizon, source observations can be triggered. An authorized
   independent reviewer compares dated evidence to original criteria. View each
   version's Outcome history; Profile and Activity link permitted recorded events.
